Longer form than a resume bullet. Each of these started as somebody being blocked, and each is written up with the constraint that actually shaped the answer.

  1. Tomorrow.io 2022 — 2024

    Getting myself off the critical path

    Research teams were waiting on infrastructure review for changes that were routine, and data problems were being found late, by hand. Both were really the same problem: the people closest to the work could not see or change the things they depended on. Adding reviewers would have scaled the bottleneck, not removed it.

    What I built

    • A data validation UI that gave the team a direct view of integrity checks, which changed how operational work got done day to day.
    • Terraform packaged into reusable modules with automation scripts, making the common deployment paths safe by default so scientists and engineers could ship without me.
    • Enablement material for integration workflows, so adoption did not depend on someone remembering to explain it.

  3. Tomorrow.io 2022 — 2025

    Rust ingest for global weather data

    Weather models publish on a fixed cadence, so the data arrives in bursts: quiet, then an enormous worldwide volume all at once. Ingest had to absorb the spike without paying for peak capacity through the quiet hours, and it had to be correct, because a silently dropped observation surfaces later as a wrong forecast in front of a customer.

    What I built

    • Rust ingest applications and the shared internal libraries behind them, raising throughput and reliability across pipelines.
    • KEDA-based serverless scaling so capacity followed the publish cadence rather than peak load, later moved to ScaledJobs in GCP for further savings.
    • Datadog dashboards and observability practices that surfaced ingest failures before they reached forecasts.
